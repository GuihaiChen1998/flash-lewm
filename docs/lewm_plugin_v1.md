# 用在原版 LeWM 上：即插即用验证（v1，2026-11-18）

问题：我们的方法（FlashCEM、承诺前缀、min 代价）是在 Fast-LeWM 上做的。直接换成原版 LeWM（Maes et al. 2026，HF 权重
`quentinll/lewm-{pusht,tworoom,cube,reacher}`），不改模型、不重训，是否同样有效？

## 结论

1. **不改模型、不重训就能用**：只加了一个加载器（`flash_lewm/lewm.py`）和一个逐块自回归预测的代价函数（`plan_cost` 的 LeWM 分支），
   与官方 `get_cost` 的最大相对误差 2.5e-4。
2. **原版 LeWM 按官方方式部署在 10 Hz 下基本不可用**：官方 CEM 300×30 每次规划 5.5 s（每轮把 300 个候选的图像重新编码），
   折合 56 步延迟，超过 50 步预算；8 个环境-场景里成功率 0–8%。
3. **我们的方法在 LeWM 上同样显著有效**：完整方法对官方部署 +20 到 +99 个百分点（8 组全部显著）；
   对「只缓存编码」（延迟 6 步、整段执行、终点代价）+8 到 +77（6 组显著，Cube 换目标持平，Push-T 静态边缘显著）。
4. **完整方法不比零延迟的官方做法差**：8 组里 4 组显著更好（Two-Room 静态 +4、Cube 静态 +9、Reacher +13 / +35），其余差异不显著。
5. **叠加到 iCEM / MPPI 上也成立**：16 组里 13 组显著提升（+9 到 +41），不显著的 3 组都在 Cube。
6. 与 Fast-LeWM 不同的一点：**原版 LeWM 的主要耗时在预测器**（逐块自回归，每轮 5 次 Transformer 调用），
   编译只把 617 ms 降到 557 ms，大头加速来自「编码只做一次」（5.5 s → 0.6 s，约 9 倍）。所以在 LeWM 上延迟仍是 6 步，
   承诺前缀用 2 块队列（`clamp:2:6`）。

## 耗时（RTX A6000，Push-T 权重，`scripts/e11_solver_latency.py lewm_pusht`）

| 求解器 | 耗时 | 10 Hz 延迟步数 |
|---|---|---|
| 官方 CEM 300×30（每轮重新编码） | 5509 ms | 56 |
| CEM 300×30（编码缓存） | 617 ms | 7 |
| **FlashCEM 300×30（编码缓存 + 编译）** | **557 ms** | **6** |
| iCEM 100×5（编码缓存） | 114 ms | 2 |
| iCEM 100×5 按官方方式部署（估算：缓存版 + 每轮重新编码约 54 ms） | ≈ 386 ms | 4 |
| 官方 MPPI 300×10 | 463 ms | 5 |
| MPPI 300×10（编码缓存） | 211 ms | 3 |

四个环境的 LeWM 结构相同（ViT-tiny、6 层预测器、3 帧历史），只有 Cube 的动作维度不同（25 对 10），延迟统一按 Push-T 的实测值。
TF32 只快 14%，bf16 不更快，都没用。官方库的 iCEM 在 LeWM 上同样报错（动作维度不匹配），所以 iCEM 用我们的实现。

在 LeWM 上，MPPI + 部件（3 步延迟、每块重规划）在 Push-T、Two-Room 上与完整方法打平：LeWM 的规划太慢，
6 步延迟下完整方法只能每 2 块重规划一次，而 MPPI 每块都能重规划。这说明部件与求解器可自由组合，选哪个求解器取决于它在目标模型上的速度。

## 局限

- 每组只有 100 回合（LeWM 规划慢，300 回合约 3 倍时间），置信区间比 Fast-LeWM 的宽一倍左右。
- 只跑了实时闭环；没在原版 LeWM 上跑官方 `eval.py`（官方协议下 5.5 s × 每回合约 10 次 × 50 回合，可以补）。
- Cube 上 LeWM 本身成功率低（零延迟 20–24%），差异多数不显著。
- 延迟用 Push-T 权重测得的值套到四个环境。

## 复现

```bash
# 权重：huggingface-cli download quentinll/lewm-pusht --local-dir ckpt/lewm/pusht（其余环境同理）
FLASH_ENV=pusht FLASH_ADIM=2 FLASH_CKPT=ckpt/lewm/pusht python scripts/e9_realtime.py 50 LWpushtswitch \
  sync:5:56:30:last:switch sync:5:6:30:last:switch clamp:2:6:30:min:switch sync:5:6:30:min:switch oracle:5:0:30:last:switch
FLASH_SOLVER=icem FLASH_N=100 ... scripts/e9_realtime.py 50 LWIpushtswitch sync:5:4:5:last:switch clamp:1:2:5:min:switch
FLASH_SOLVER=mppi             ... scripts/e9_realtime.py 50 LWMpushtswitch sync:5:5:10:last:switch clamp:1:3:10:min:switch
python scripts/e11_solver_latency.py lewm_pusht 10     # 耗时（FLASH_CKPT 指向 LeWM 目录）
```

其他环境的数据、回合文件环境变量与 `docs/real_latency_v1.md` 相同，只把 `FLASH_CKPT` 换成 `ckpt/lewm/<env>`。
