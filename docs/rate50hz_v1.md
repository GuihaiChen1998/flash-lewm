# 50 Hz 控制下与 iCEM、MPPI 的对比（v1，2026-11-18）

问题：10 Hz 时，任何低于 100 ms 的求解器都只算 1 步延迟，iCEM 的速度优势体现不出来。把控制周期缩到 20 ms（50 Hz），
iCEM 省下的时间会不会变成成功率？

## 设定

环境、模型（Fast-LeWM 官方权重）、回合（每组 300 个）都与 `docs/sampling_baselines_v1.md` 相同，只把控制周期从 100 ms 换成 20 ms：
延迟步数 = ⌈实测耗时 / 20 ms⌉。这相当于「计算相对环境慢 5 倍」，动作块仍是 5 步（现在是 100 ms）。

| 求解器 | 实测耗时（Push-T / Cube） | 50 Hz 延迟步数 |
|---|---|---|
| 官方 CEM 300×30 | 453 / 568 ms | 23 / 29 |
| **FlashCEM 300×30（编译）** | 62 / 63 ms | **4 / 4** |
| FlashCEM 300×10（编译） | 24 / 26 ms | 2 / 2 |
| FlashCEM 300×5（编译） | 15 / 16 ms | 1 / 1 |
| iCEM 300×10：官方方式部署（估算） / 缓存 eager 实测 / 按编译后等价 | 161 / 59 / 24 ms（Cube 203 / 76 / 26） | 9 / 3 / 2（Cube 11 / 4 / 2） |
| iCEM 100×5：同上三档 | 52 / 35 / 10 ms（Cube 65 / 44 / 10） | 3 / 2 / 1（Cube 4 / 3 / 1） |
| MPPI 300×10：官方 / 缓存 eager / 按编译后等价 | 148 / 55 / 24 ms（Cube 187 / 71 / 26） | 8 / 3 / 2（Cube 10 / 4 / 2） |

FlashCEM 各档耗时来自 `scripts/e12_flash_iters.py`。「按编译后等价」假设 iCEM、MPPI 也像 FlashCEM 一样编译，
耗时取同样候选数 × 轮数的 FlashCEM 实测值。这对它们最有利，用来回答「是不是只有我们的方法被编译了」。
Two-Room 用 Push-T 的延迟，Reacher 用 Cube 的延迟（架构相同、耗时一致）。

## 结论

1. **50 Hz 下完整方法对官方部署的优势更大**：官方 CEM 要冻结 23–29 步，完整方法（FlashCEM 300×30，4 步）8 组全部显著更好，
   +5.7 到 +80.3 个百分点（10 Hz 时是 +6.0 到 +66.0）。
2. **iCEM 的速度优势在 50 Hz 下仍然没有变成成功率**：同一个 iCEM 加上我们的部件后，延迟 2 步（按编译后等价）和 3–4 步（eager 实测）
   在 8 组里有 6 组差异不显著，Cube 的 2 组反而是延迟更短的略差。
   原因在承诺前缀：每块（5 步 = 100 ms）重规划一次，规划只要在这一块执行完之前算完，延迟就被完全藏住，只多付一次开头的等待。
   所以只要耗时低于一块的时长，再快也没有收益；决定成功率的是每次规划的质量。
3. **完整方法高于「iCEM / MPPI + 我们的部件」，即使给它们按编译后的耗时算**：
   对 iCEM 300×10 6 组显著更好、2 组持平（Push-T 静态、Two-Room 静态）；对 MPPI 300×10 7 组显著更好、1 组持平（Two-Room 静态）。
4. **同预算、同延迟下 CEM 也不比 iCEM 差**：FlashCEM 300×10 与 iCEM 300×10（都是 2 步延迟，都加部件）相比，6 组显著更好，2 组持平（Push-T 静态、Two-Room 静态）。
5. 叠加仍然有效：50 Hz 下给 iCEM、iCEM-小、MPPI 加上部件（按 eager 实测延迟），24 组里 20 组显著提升，其余 4 组持平（3 组是 Cube 换目标，1 组是 Reacher 换目标的 iCEM）。

所以「iCEM 等采样优化」与我们的方法的关系是：它们能让每次规划更快或更准，但在有承诺前缀的执行方式下，只有当规划耗时超过一个动作块时
速度才重要；我们的 FlashCEM 在 10 Hz 和 50 Hz 下都已经低于一块（500 ms / 100 ms）。速度真正关键的情形是更高的控制频率或更短的动作块
（例如 250 Hz、块长 20 ms），这里没有测。

「iCEM：编译等价 − eager」在 Push-T 上恰好为 0：两者都每块重规划，只差开头多等 1 步（原地不动），轨迹只是整体平移一步。
Cube 上机械臂停顿时会有微小漂移，所以开头的等待长短会带来差异。

## 局限

- 「50 Hz」是把延迟步数放大 5 倍的近似，环境动力学和动作块仍是原来的；真实 50 Hz 机器人的动作块和模型都会不同。
- 仿真器假设每块执行期间规划在后台并行进行，没有模拟 GPU 被其他任务抢占。
- iCEM、MPPI 没有逐环境调参；「官方方式部署」的 iCEM 延迟是估算值。

